# Nous 训练工坊 Spec

当前进入交互评审。

[打开训练工坊原型](assets/2026-11-20-training-studio/index.html)

## 目标与首期范围

在 Nous 内完成选图、标注、备齐训练模型、启动训练、比较样图和发布 LoRA。已适配的训练模型在本地扫描或下载校验后即可选用。用户无需手写路径、训练命令或模型配置。

工坊入口为管理控制台的 `/training`。原型可在浏览器离线打开。示例显存、批量标注、模型下载、训练、试载和发布均为演示，刷新页面会重置。上传图片仅在当前页面内预览。首期实现先验证 Qwen-Image-2.1 文生图 LoRA，再接 MOSS-Image Base 和 SFT。后续增加编辑数据集，分别保存参考图、目标图和编辑指令。

## 界面结构

页面头部沿用 Nous 的资源监控，在工坊导航旁显示训练队列数和环境状态。四个页面共享当前数据集、模型和任务上下文。窄屏下将侧栏折叠，表单和预览纵向排列。

| 页面 | 内容与操作 |
| --- | --- |
| 数据集 | 从图库加入、上传文件、导入同名 TXT。网格和表格可切换，支持搜索、已标注与待标注筛选、多选。右侧查看或修改图片描述，也可用选定视觉模型批量反推。底部显示本次训练所选素材数。 |
| 模型与目录 | 同时展示训练配方和本地安装状态。支持按家族、任务类型、就绪状态筛选。卡片操作随状态变化，提供扫描、下载、补齐、查看组件及配置训练。 |
| 训练任务 | 发起训练和查看记录共用一个页面。基础项为任务名称、数据集快照、模型配方、GPU 和训练预设。步数、分辨率、Rank、学习率、保存间隔放在高级参数。详情展示 GPU、环境、磁盘预检，以及运行阶段和日志。 |
| 结果与发布 | 同提示词和种子比较底模与选定 checkpoint，可滑动对比。展示 Loss、样图、生成参数和可下载产物。明确试载结果、目标目录和重名提示，确认后将 LoRA 发布到对应家族目录。 |

## 操作与状态

### 数据集和标注

- 从图库引用的素材创建受管理副本，记录原素材来源。同名 TXT 按相对路径配对，导入前报告冲突和未配对项。手动编辑保留修订版本。
- 批量打标默认只写空描述。重做已标注项需明确选择覆盖，展示预定处理数量。打标记录描述模型、模板、结果和文件级错误，支持仅重试失败项。
- 发起训练时冻结所选素材、标注版本和顺序。训练记录引用快照，数据集后续编辑不改变当次训练输入。
- 基础图片数据允许训练者明确确认空描述样本。编辑数据集的输入图、目标图和指令后续独立校验。

### 下载、扫描和训练配方

- 训练配方声明模型家族、变体、模式、支持的训练参数、上游仓库及修订版本、组件清单、允许的格式和校验条件。模型路径和配方版本保存在本机登记中。
- 扫描限于管理员配置的模型根目录。发现兼容组件时只登记路径。文件存在但架构或格式不兼容时标为「需要转换」或「组件待补齐」，显示具体文件和原因。推理可用、训练可用分别显示。
- 「模型与目录」默认使用魔搭 ModelScope，也可选 Hugging Face 或扫描本地已有权重。配方按来源记录仓库 ID、修订版本及组件映射。同一模型在不同社区可能有不同的仓库名和文件布局，切换来源后按对应清单校验。下载前列出目标位置、预计体积、可用空间和待下载文件。下载任务使用暂存目录，校验通过后导入并登记。取消和重试支持保留可续传的暂存数据。已有兼容组件可复用。
- 从模型卡点击「配置训练」时保留已经选好的数据集。卡片从「未下载 / 组件待补齐」流转到「排队 / 下载中 / 校验中 / 可训练」，失败后保留错误说明和重试入口。
- 训练环境独立于 Nous 推理和 ComfyUI，设置页检测训练器版本、Python 环境、CUDA 及模型目录，返回单项检查和诊断。模型登记完成仅使配方可选，训练仍由用户提交。

### GPU、任务和恢复

- 工坊管理 API 使用现有管理员权限。训练 runner 在独立 Python 环境执行版本固定的 DiffSynth 入口，通过参数数组启动。队列持久化任务、产物、日志和运行状态。
- 提交前校验数据快照、模型组件、保存目录、环境和 GPU 选择。GPU 使用可用显存和现有推理占用评估，调度器按受控 GPU 互斥规则排队。训练 runner 不向生产推理进程发送中断请求。
- 任务流转为「排队 → 准备数据 → 训练 → 保存产物 → 完成」，各阶段可报告失败或取消。进度记录步数、阶段和耗时。重试和续训保留原任务配置并关联来源。
- 推断样图独立排队。对比记录模型、checkpoint、提示词、种子、参数及样图。下载与训练结果逐项展示，浏览器刷新后可重新进入同一任务。

### 发布

- 可下载单个 checkpoint 或最终权重。试载时验证实际目标 ComfyUI 工作流和 LoRA 家族，记录结果并保持可追溯。
- 发布支持 `qwen2.1` 和 `moss`。目标路径由家族配置推导，文件名重名时提示改名或确认覆盖。完整写入后同步 LoRA 目录，使文件出现在相应的工作台筛选中。
- 训练历史保留数据集快照、训练配方版本、GPU、参数、产物和发布位置。训练结果可以保留多个版本。

## 接入契约

| 对象 | 冻结或持久化内容 |
| --- | --- |
| 数据集与快照 | 素材引用、媒体尺寸、标注、筛选后的选择顺序和修订版本 |
| 配方与本机模型 | 上游来源和修订版本、必需组件、绝对路径、验证结果和训练模式 |
| 下载任务 | 来源、组件清单、目标目录、字节进度、失败原因和重试状态 |
| 训练任务 | 快照 ID、配方版本、GPU、训练参数、阶段、步数、日志和 checkpoint |
| 产物与发布 | 文件、格式、校验和、样图、试载反馈和发布目标 |

前端复用 Nous 的图库选择器、资源状态和主题。后端参考 DiffSynth-WebUI 的数据集与任务实现。训练由版本固定的魔搭开源 DiffSynth-Studio 在 Nous 主机的独立环境中执行，读取已校验的本地权重与数据集快照。模型下载来源与训练任务解耦，换下载来源时无需更换训练器。图库和 LoRA 同步继续使用 Nous 入口。模型注册表热加载属于现有推理引擎管理接口，训练配方单独登记。

## 验收和实施顺序

1. **原型评审**。验证素材多选、反推与修订、缺件补齐、开始训练、checkpoint 对比与发布。确认用户不必在任务间重复配置路径。
2. **Qwen-Image-2.1 文生图闭环**。同一数据集快照可重跑。正常训练与失败均能刷新恢复，导出 LoRA 在现有 ComfyUI 工作流试载通过。下载失败重试不会重复登记同一模型。
3. **MOSS-Image Base/SFT**。分别验证训练配方和权重兼容性，报告运行时显存占用与样图。扩展 GPU 队列验证，保持已部署推理正常。
4. **编辑 LoRA**。增加参考图与目标图配对、编辑描述、按同一参考图比较样图。
